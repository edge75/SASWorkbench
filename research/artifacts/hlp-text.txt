MINIMUM SYSTEM REQUIREMENTS
SASTest
  requires:
An IBM Compatible Computer using at least a 200 mhz Pentium processor Windows 95/98/NT/2000/XP or higher, with 24 meg of ram.
INSTALLATION
Just copy the SASTest.exe and SASTest.ini and this help file to any directory you wish.
To have it start from a  different COMM port: 
1. Create A Shortcut in Windows 95/98 or NT. 
2. Then edit the shortcut.
3. Fill in the description box with any title you like.
4. To select the comm port you are using, you must go to the INI file and under the SAS Protocols section specify the port . 
example: port = 2   
The above line sets the comm port to comm2.
OVERVIEW
The SASTest program allows you to test AFT - EFT 
 ECT - SBM - SAS commands using
the standard Windows point and click method. It is INI file driven, meaning that all commands and responses can be setup and changed in the SASTest.INI file. 
  Auto Ticket Redemption/Validation is now supported, which allows complete testing of the ticket in ticket out process.
Please remember the actual bytes transmitted and received is what is important!!! The English message window is just a convenience and if your INI file is incomplete these messages may not get translated.  
Known Problems / Eccentricities
Since the SAS protocol uses a "wake up bit" (a 9th bit) for machine addressing we have to use the parity bit as a substitute. Under DOS this would be no problem because there is direct access to the serial port hardware.  Windows on the other hand, isolates the program from the hardware using virtual drivers. For this program to be compatible with all the available COMM drivers out there, we had to use purely Windows API commands filtered through the COMM driver. This creates problems switching the parity bit on and off
as necessary, because Windows requires you to totally re-initialize the COMM port and it is virtually impossible to determine if the byte with the wakeup bit really went out of the UART. Also Windows COMM drivers do not have any facility to mark any one byte received with an error, it can only let you know if any byte in the UART buffer has an error, making it again virtually impossible to tag an individual byte . Also Windows schedules usage of any process (thread) taking away time to let other apps use its multi-tasking. The receive buffer in this program uses a separate thread for reading the bytes coming in. Since it is unknown how many bytes are really coming in we have to wait for a time out. This causes polling cycle timing problems as well as response time problems when the game requires an ACK, Windows has a tendency to chop up your message causing the machine to time out.  There are times when things get out of sync with the messaging. Always look in the bottom window if something looks weird. Also if you have a slow machine Windows may want to 
chop up
 the return message.
  In recent years as the processors get faster these problems become less and less prevalent.

INVOKING A SAS / LONG POLL COMMAND
To invoke a SAS command press the small down arrow on the right side of the Long Poll Commands dropdown. Then pick the command from the list, the lower window will show what commands were sent in hex denoted by a TX= and what bytes were received denoted by a RX=. The upper window will show in English what was returned. Please note, if the English statement is not in the window it is probably not listed in the ini file. 
INVOKING A ECT/EFT COMMAND
To invoke a ECT/EFT command press the small down arrow on the right side of the ECT/EFT Commands dropdown. Then pick the command from the list, the lower window will show what commands were sent in hex denoted by a TX= and what bytes were received denoted by a RX=. The upper window will show in English what was returned.

FIBER OPTIC SUPPORT
Sas test can now be used with fiber optics, such usage requires that the program allows the bytes it sends out to be echoed back and ignored. It seems that Win98 and WinNT handle the received characters differently. So to compensate there is an entry in the sastest.ini file to index that properly, just in case there is a problem. Also with this new functionality you can redeem tickets from multiple machines on the loop. The only caveat is the machines being polled must be on the loop you cannot poll a machine that doesn
t answer at this time. 
NEW REPORT BUILDING TOOL
The SAS tester now has a report building tool. The way it works is it records the entire transaction into a buffer and you can insert that recorded data into the memo box on the report page. The buffer is cleared each time you select the long poll drop down, EFT drop down, or send a custom command. This feature doesn
t work with scripting.

You can now save most of the settings you have chosen in a .SET file. You may make as many with different configurations as you wish. The options are found under the File menu.

FIBER OPTIC SUPPORTbI &

Sas test can now be used with fiber optics, such usage requires that the program allows the bytes it sends out to be echoed back and ignored. It seems that Win98 and WinNT handle the received characters differently. So to compensate there is an entry in the sastest.ini file to index that properly, just in case there is a problem. Also with this new functionality you can redeem tickets from multiple machines on the loop. The only caveat is the machines being polled must be on the loop you cannot poll a machine that doesnt answer at this time.
