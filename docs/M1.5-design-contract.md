# M1.5 — Design contract

The window built in M1 was a protocol debugger with a Run tab stapled to it: four style rules, no
colour tokens, seven levels of `Opacity` standing in for a hierarchy, and one line of 11 px grey
text carrying the provenance that D-principle 4 calls load-bearing. This milestone rebuilt it on a
contract, before M2, M3 and M4 each add a panel to it.

The direction was chosen with the user at the end of the design phase and is recorded as **D21–D28**
in `.planning/DECISIONS.md`: the **Session Bench** shell over a session-stream substrate, in the
**Bench** visual direction. The proposals it was chosen from are in `.planning/design/`.

---

## What was built

### The token dictionary

`src/SasWorkbench.Gui/Themes/Tokens.axaml` — thirty-seven tokens, defined in full for both light
and dark, plus the two font stacks. `Themes/Components.axaml` holds every style that consumes them.

**Opacity no longer expresses hierarchy anywhere.** Hierarchy is four text tokens, weight, size,
case and position. A test enforces it: `NoViewExpressesHierarchyWithOpacity` fails the build if an
`Opacity` attribute reappears in any view. Two further tests check that both theme variants define
exactly the same keys and that every `DynamicResource` a view asks for exists — the failure mode
otherwise is silent, because an unresolved brush renders as nothing at all.

### The three status families

Verdicts are chips, data states are angle-bracketed, provenance stamps are double-bracketed. The
three can never be read as each other.

A chip carries **three redundant cues**: the word, a fill treatment, and a vector glyph drawn as
geometry rather than as a font character. Pass and fail cannot be separated by colour under
deuteranopia in any palette measured for this contract — between 1.00:1 and 1.19:1 across all eight
variants — so those three cues are the whole mitigation, and **FAIL is the only solid-filled chip in
the application**. Every chip carries an automation name of the word plus the reason.

The angle brackets are probed once at startup and swapped for ASCII when the resolved fonts cannot
draw them, so a minimal font set produces `<unknown>` rather than a blank box.

### The shell

Four bands — instrument header, provenance rail, body, footer readout — with the body split into an
instrument rail, the spine, and one instrument at a time.

The provenance rail is no longer a line of grey text. It is a full-width band whose ground changes
with the strength of the claim, carrying the seal, the link, what is driving it and the caveat, and
it is announced to a screen reader as a live region. The footer repeats the claim, so a cropped
screenshot still carries it.

The rail lists the instruments a later milestone brings — stimulus, tickets, traces, catalogue,
session — marked with the milestone and not selectable. A surface that is coming and a surface that
is missing are different things to a reader.

### The session stream

The centre is not a wire log. `SasWorkbench.Core.Session` now holds one time-ordered record of
everything a session did — transmit, receive, exception, stimulus, prompt, assertion, verdict, link
state and test boundaries — each event carrying its channel, on **one clock**.

That clock is the part worth stating. A poll engine measures from the moment it started and a test
measures from the moment it began, so a frame at 5927 ms and a step at 12 ms can be the same
instant. `SessionClock` marks each source's zero as it starts, and `ClockBase` converts. Without it
"within five seconds" is a claim about two different zeroes.

Turning the assertion lane on is a checkbox, not a different view. One log per session whatever the
channel count, so two hosts interleave here rather than producing two logs to align later.

**Timestamps read three ways** — since the test started, since the previous poll on that channel,
since the previous message — chosen per view and never written into the record. The distinction is
the point: in a 200 ms poll loop the second reads the loop period and the third reads the 30.7 ms a
reply took, and they answer different questions.

**The wakeup bit is a display setting.** Colour only by default: the byte alone, with an address
byte drawn in the wakeup colour. Flag-digit mode restores `1.80`. This needed the symbols to travel
as a list rather than as a joined string, because a joined string cannot highlight bit 8.

### The suite instrument

A tree of the corpus, built by parsing rather than by running, so the tests are visible before
anything is connected. Each node carries a chip; a folder takes the worst verdict beneath it, so a
red test cannot hide inside a green tree; a test that has not run reads as `NOT RUN` rather than as
absent.

Selecting a test narrows the stream to its own window, and the panel shows **every step including
the claims that held**, the frames the test captured, and a provenance seal for that test in
particular.

## The four defects this milestone found and fixed

Found by reading the M1 source against the contract, not by a failing test.

1. **A test needing a person could not run from the window at all.** The prompt delegate was only
   ever set by the command line, so a `manual` step was unreachable from the interface.
2. **A manual prompt had no deadline.** An unattended run reaching one hung for ever and produced no
   verdict — a silent failure in a product whose first principle is that nothing fails silently.
   A prompt now takes a deadline that cannot be omitted, and nobody answering is a skip that says
   `nobody answered within 45s`, consistent with the rule that an unavailable capability skips.
3. **The window discarded every assertion that passed.** A reader could not tell a claim that held
   from a claim that was never made.
4. **The window offered channels 2 to 4 as ordinary choices** while the capability probe advertised
   only the first. They now render as a data state with the reason attached.

A fifth, found while building: **arrival order is not occurrence order.** The wire is recorded on
the poll thread and a step on the runner thread, so a frame that happened first can be appended
second — by the whole duration of a long poll, around 30 ms. The log's canonical order is now the
clock; the sequence number stays the arrival order, which is what tells a reader whether anything
was dropped.

A review of the milestone's own code found four more, all fixed: a prompt answered in the same
millisecond the deadline passed could be accepted by the interface and discarded by the run, and
could throw on the interface thread; a second session pointed at the stream would have measured its
first event from the last event of the one before; a test's name was attached outside the lock that
appends the event opening it; and the dropped-event counter was read without the lock that writes it.

## Deviations from the contract, and why

* **The wakeup ground was dropped.** The contract gives a wakeup symbol a tinted ground. On a
  transmit row, which already carries a tint of its own, that ground is invisible — measured against
  the row colour rather than against the sunken well it was specified for. Colour and weight only.
* **A seventh chip state, ERROR.** The contract lists six; `Verdict` has four, and error is one of
  them. It is outlined and tinted in the failure colours with a heavy leading bar and an exclamation
  glyph, so **FAIL remains the only solid-filled chip** and the accessibility claim stays true.
* **Drawers became an instrument rail.** The Bench proposal used an expander stack; the chosen
  hybrid (D21) uses A's rail with one instrument at a time. This is what was decided, not a
  departure from it, and is noted only because the UI proposal's own wireframes show drawers.
* **The report *mode* was not built.** The contract grafts a document-shaped view of a run from the
  Dossier proposal, explicitly demoted by D24. What was built is report *writing* — the window
  produces the same self-contained page the command line does, into `runs/<timestamp>/`. The
  in-window rendering of it is deferred until there is a reason to look at one on screen.
* **A run's link can be overridden from the window.** The contract asks for an explicit link
  selector; the command line already had one. Rather than write it twice, the override moved into
  Core as `ConnectionOverride`, and both front ends apply the same one — so `--tcp` from the command
  line and *over: tcp* in the window mean exactly the same thing.

## Looking at it

`tools/ui-specimen` renders the window off-screen, both themes and both sizes, filled with the
frames M1 actually captured and with the committed regression suite genuinely run — so what the
picture shows is what the tool shows. It also renders every chip state on one sheet, which is how
the three-cue contract gets checked rather than assumed, and it turns on Avalonia's binding
diagnostics, so a mistyped binding is caught by a render rather than by an empty cell at runtime.

```
dotnet run --project tools/ui-specimen -- artifacts/ui
```

Development only; nothing in it ships in a release.

---

## Sizes

The window is 1180x760 by default and 900x600 minimum. On a 1366x768 laptop at 125 % scaling the
usable area is 1092x614 DIP, so **the minimum layout is the common case, not the edge case**. The
body columns are proportional with minimums rather than fixed, and both sizes are rendered on every
specimen run for exactly this reason.
